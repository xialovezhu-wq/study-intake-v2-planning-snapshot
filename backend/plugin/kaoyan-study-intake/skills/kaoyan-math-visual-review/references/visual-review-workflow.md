# Visual Review Workflow

## 1. Resolve The Requested Outcome

Choose one primary result: chat review, narration script, structured Markdown, or HTML artifact. Route formal intake and explicit old-question selection before composing the review.

## 2. Build A Minimal Evidence Table

Start from the user summary, named formal IDs, an existing daily-filter shortlist, and relevant wiki or method-gap pages. Record for each claim its source and whether it is verified, inferred, or missing.

Use Obsidian to locate stable notes when needed. Use Chronicle only when the request depends on recent visible context; carry forward likely topics or IDs as locators, then verify them in stable sources.

Stop retrieval when the core conclusion, error patterns, priority questions, and tomorrow actions are supported. Do not keep searching to add examples or polish.

## 3. Synthesize The Review

Create one narrative:

1. today’s central problem;
2. evidence-backed error patterns;
3. the method gap and correct first action;
4. how the available priority questions illustrate it;
5. tomorrow’s ordered actions.

Use `output-structure.md`. If HTML is the primary artifact, also use `html-review-template.md`.

## 4. Apply The Write Boundary

Ordinary reviews remain in chat. An explicit artifact request may create one file in an existing safe location. Tutor sync runs only when explicitly requested. Follow `safety-boundaries.md` for all writes.

## 5. Validate And Finish

Check evidence coverage and missing fields. Render HTML when applicable. Confirm protected formal data is unchanged, then report the artifact path or chat-only result and any unresolved evidence.
